# Agent context

## Stack

Astro 7 (output statico) · React 19 come **isole** · TypeScript · Tailwind CSS v4 ·
pnpm 11 · **No test framework** · Deploys via Vercel

`package.json` pins `packageManager`: `pnpm@11.22.0`. Contact form is **Web3Forms + hCaptcha** (no backend, no Supabase).

## Commands

| Action         | Command               |
| -------------- | --------------------- |

| Build          | `pnpm build`          |
| Preview        | `pnpm preview`        |

Before closing non-trivial changes, run `pnpm build`, `pnpm lint`, `pnpm typecheck`, and `pnpm audit --audit-level high`. There is no CI workflow in the repo.

## Project structure

- **Astro config is at repo root** (`astro.config.mjs`): `site` is the Vercel URL, `output` is `static`, integrations `@astrojs/react` + `@astrojs/sitemap`, Tailwind v4 via `@tailwindcss/vite`
- **1 file per route** in `src/pages/`: `index`, `about`, `studies`, `skills`, `projects`, `contact` (`.astro`). `sitemap-index.xml` is generated by the sitemap integration
- **`src/layouts/BaseLayout.astro`** holds the whole `<head>` (title/description props, canonical, OG/Twitter, Person JSON-LD), the header markup, the footer and one inline script (reveal-on-scroll + `data-scrolled` on the header)
- **SEO rule: content must be real HTML, never rendered client-side.** A page rendered by React without a `client:*` directive is prerendered to static HTML — that is the default and the wanted behaviour
- **Only 3 islands ship JS:** `MobileMenu` (`client:media="(max-width: 767px)"`), `ProjectsCarousel` (`client:visible`), `ContactPage` (`client:load`). Adding a `client:*` directive adds React to that page: don't, unless there is real interactivity
- **Page copy/data** lives in `src/lib/` (`about.ts`, `experience.ts`, `projects.ts`, `skills.ts`, `study.ts`, `navigation.ts`) — edit those modules, not hardcoded strings in page components
- **CSS:** Tailwind v4 `@theme` custom tokens + component classes in `@layer components` inside `src/index.css`
- **Static assets** (images, CV PDF, logos) are centralized via `src/lib/static-assets.ts` — use that module, not raw paths. Skill icons are static URLs from `skill-icons.ts` (`?url` imports), rendered by `LazySkillIcon` with native `loading="lazy"`
- **`Reveal`** adds the `data-reveal` attribute and the class `reveal-scroll`; the layout script adds `data-visible`. Do not add a class via JS to React-rendered nodes: hydration would fight it
- **`vercel.json`** sets only security headers (no rewrites: every route is a real file). CSP allows `'unsafe-inline'` scripts because Astro inlines its hydration bootstrapper — keep hCaptcha/Web3Forms origins in sync
- **Fonts:** `@fontsource-variable/bricolage-grotesque` + `@fontsource/hanken-grotesk`, imported in `BaseLayout.astro`
- **pnpm-workspace.yaml** pins transitive security overrides; keep it when bumping Vercel/CLI deps

## Design specs

- **PRODUCT.md** — register (`brand`), users, purpose, personality, anti-references, principles, accessibility
- **DESIGN.md** — OKLCH tokens, typography, elevation, components, do's and don'ts

Register default: **brand** (personal portfolio; design is the product).

## Notes

- There is no CI and no pre-commit hooks. Typecheck is `pnpm typecheck` (`astro check`).
- Contact keys (Web3Forms access key, hCaptcha sitekey) are public by design and live in `ContactPage.tsx`. Do not move them to a backend-style secret.
